# Pipeline Eval

跨运行评估。用户主动调用，不修改任何文件，只产出诊断报告。

## 输入

读取最近 N 次运行的 .claude/pipeline-log.md（默认 N=5，可通过 $ARGUMENTS 指定）

## 4 目标评估框架

每个目标由多个检查项组成，加权计分。**必须有执行证据才给分。**

### 目标 1: 编排正确性

| 检查项 | 权重 | 评分标准 |
|--------|------|---------|
| 阶段顺序正确 | 20% | 顺序与 CLAUDE.md 一致 |
| 无跳步/合并 | 15% | SR-0 全部合规 |
| 失败正确处理 | 15% | review 不通过后有修复重审循环；主 agent 写入评审结果到 state |
| State 正确更新 | 10% | SR-6 全部合规 |
| 日志结构完整 | 10% | 每个阶段有五段 + SR + QR + 观察 |

### 目标 2: 子 agent 质量

| 检查项 | 权重 | 评分标准 |
|--------|------|---------|
| 知识加载完整 | 15% | SR-1/SR-2 全部合规 |
| Act 步骤遵循 | 15% | SR-4 全部合规 |
| Verify 有证据 | 10% | SR-5 全部合规（每项有具体验证方法，非只打勾） |
| 无越界 | 10% | SR-7 全部合规 |

### 目标 3: 知识传递有效性

| 检查项 | 权重 | 评分标准 |
|--------|------|---------|
| Handoff 完成 | 20% | SR-3 全部合规（非首阶段），5 个字段全部填写 |
| References 可达 | 15% | 全部完整路径，无索引跳转 |
| 知识回流触发 | 15% | SR-8 全部合规（Issue 摘要、ADR、knowledge 更新均已触发） |
| Review 独立性 | 10% | review 只读 state+产出+review.md，未读被评审 stage |

### 目标 4: 产出可交付性

| 检查项 | 权重 | 评分标准 |
|--------|------|---------|
| 测试通过 | 20% | make test && make lint 零错误（非代码交付标记 N/A） |
| PR 质量 | 20% | 变更摘要+模块列表+知识变更+测试结果+偏差说明齐全 |
| Issue 关联 | 10% | Closes #N 正确 |
| 无无关文件 | 10% | git diff 无范围外文件 |
| 知识文件同步 | 10% | deliver 阶段确认知识文件变更在 diff 中 |

### 评分规则

- 每个检查项：满分/半分/零分
- 每个目标 = 加权求和
- 总评 = 4 个目标的平均值
- **meta-task 环境限制**（如无法跑 make test）不扣分，标记 N/A，在总评中排除

## 产出质量分析（QR 聚合）

独立于 SR 合规率，单独分析 QR-0 ~ QR-3：

| QR 项 | 合规率 | 典型偏差模式 |
|-------|--------|-------------|
| QR-0 决策一致性 | X/N | {或 —} |
| QR-1 边界合规 | X/N | {或 —} |
| QR-2 验收可验证 | X/N | {或 —} |
| QR-3 下游可用性 | X/N | {或 —} |

**SR 全部合规但 QR 有偏差的运行**标记为"合规但低质"——这比 SR 偏差更危险。

- 总补读率 = 有补读的阶段数 / 总阶段数（非首阶段）

### 下游重做分析

| 重做类型 | 次数 | 触发阶段 | 根因 |
